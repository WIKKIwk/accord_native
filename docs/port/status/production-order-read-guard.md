# Production order read guard seam

The existing page, production-order detail and pending-order detail APIs accept an optional `beforeSend` callback. With no callback, the existing two-argument transport call and parsing behavior remain unchanged. With a callback, the existing `authorizedFetch` invokes it before the initial send and before a 401 retry; the API also invokes it after transport completion, body decode and final model creation, before returning data. Conditional 304 and decoded error responses are checked too. These APIs remain read-only and no route is activated by this checkpoint.

The caller must provide a synchronous throwing guard that captures the original session witness and scope, checks current route permission, and rejects stale or malformed callbacks. This seam does not implement the guard or establish native atomicity: `authorizedFetch` does not check a guard on every GET redirect hop, and JS-to-native dispatch, response failures, session changes during an already-sent request, iOS/Android native transport, existing parser and Unicode parity, and server/proxy behavior remain separate limitations. Existing worker and preparation callers are unmodified. No device or live backend was used.
