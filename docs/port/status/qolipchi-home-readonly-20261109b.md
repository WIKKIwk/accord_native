## Explicit failed-read retry

V2 `qolip_home_screen_models_resplit_part_01.dart:128-137`, `_QolipBlockGrid_resplit2_methods_01.dart:7-16`, and `app_retry_state.dart:30-65` supply the error message and retry button; `_QolipHomeScreenState_methods_01.dart:71-86,163-207,239-247` supplies the blocks reload, location future replacement and search refresh. The unmounted native candidate now connects the source retry button to a real failed blocks GET or a failed block-locations GET. It does not retry successful data, automatically retry a failure, initiate authentication, save an order or dispatch any mutation. Only one retry for a given failed state may be pending; a repeated tap while loading is ignored. This is a deliberate narrower concurrency behavior than V2's unrestricted rapid taps.

The failed location promise is replaced only by that explicit retry. Per-block generations fence the retained resolved-location cache from older completions, and the block body's FutureBuilder-style generation prevents an old future replacing a new displayed result. A successful replacement refreshes active search counts; a newer search generation supersedes an older one. The original session witness guards every initial and retry GET and each redirect hop. A session change before dispatch stops the send, and an in-flight response after invalidation cannot publish. A native GET already dispatched, including one whose client timed out, cannot be recalled; an explicit later read may overlap it. No settlement inference is made for any write, and all writes stay held.

An isolated guarded 401 produces `GuardedReadRefreshUnavailable`; this read may observe a separately initiated legacy refresh but never starts credential authentication or account/session persistence. The role shows the existing truthful V2 `qolip.home.load_failed` wording and retry label rather than asserting the session expired. If the same token remains unauthorized, a retry can fail again. A real new login plus a fresh owner can recover, as the mock integration test verifies, but this candidate does not provide a sign-in, logout, navigation or remount control; the message does not explain the 401. An independently reviewed recovery and route flow remain open.
