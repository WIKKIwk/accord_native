## Experiment and boundaries
- `src/homashyo/rawSplitJournalPrototype.ts` is unconnected and has no native adapter, transport, route, printer, independent recovery marker, outcome verifier or acknowledgment verifier. All its async operations refuse before reading or writing storage. Missing and restored journal states are equally blocked. A caller cannot unlock it by providing a Boolean, verifier or matching response.
- Fence handles are generated without caller-supplied data and have no serializable payload. They are ephemeral test handles only, not credentials and not a cross-process owner allocator. The experiment persists no token.
- `tests/support/conditionalRawSplitJournalModel.ts` is a **test-only hypothetical model**, not an implementation ready for an app. Its atomic updater, monotonic owner, legacy observations, result envelope and acknowledgment are assumed/fake. It illustrates revision fences, one active command, exact-response retention, tombstones, race handling and bounded capacity under those assumptions; it intentionally demonstrates that rollback and a new-ID repeat defeat those local checks. Application source must not import it.
- In that model, if an updater rejects before returning a value and the exact same rejection is propagated, the result is a known blocked transition under the assumed storage contract; other writers can still have changed storage. A masked callback error, storage error, post-commit error or failed post-check remains uncertain. None of the model tests proves actual Expo transaction or crash behavior.
- Do not mistake a locally matching outcome for server authority, absence of a legacy key for exclusion of old writers, or a mock test for a physical print result. Never automatically replay or print.
