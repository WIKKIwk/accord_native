# Qolipchi V2 → V4

Status: partial — role implementation and native route wiring are present; the hardware/native parity items below remain unverified.

Updated: 2026-11-17. Worktree: `accord_mobile_v4-qolipchi-port`, branch `qolipchi-port`, based on `0a07da54`. Not merged into `main`; the user's original checkout was not edited. This current report supersedes the old isolated/unwired checkpoints.

## Scope and source

- V2 baseline: `f11910bb2c8c7081ce26770e69811b03fd0739ed`; live V2 `052655a4`. No differences exist between them under `lib/src/features/qolip` or `lib/src/core/api/qolip`. The broader drift report lists unrelated shared/Admin/Metalayzer changes; its route-capability addition is Metalayzer, not a changed Qolip guard.
- Ledger: two parts, 43 public API methods, 25 endpoints and 23 named screens/sheets, plus shared scanner/printing/order-detail surfaces. Both platform implementations reuse the existing worker list, header, filter, buttons, sheet, QR, image and chat components.
- Qolipchi + `qolip.manage` enters `/android-qolip` or `/ios-qolip`. The original non-revivable account boundary owns every role page and presentation; optional request guards were threaded through source reads and writes. Other roles keep their default APIs.
- Android uses native Compose/Material controls. iOS uses native SwiftUI controls and the root native tab bar. Shared React Native layout/gesture glue retains source ordering and interaction; it is not evidence of pixel parity on a phone.

## Implemented

Home block tabs/search/reorder/cache, grid/cell details, creation, placement, sequential multi-placement, issue/worker choice, moves and scan actions; block management; complete Products and Sets catalogs, editors, shared-set reuse and conflict handling, selection, rework, rename, QR/mileage, printing and PDF sharing; checkout returns and location/product transfer; Paddons, inspection, archive filters/details/restoration and the full mold picker; compact live Tasks; read-only Sequence, order molds, assigned materials, expected results, WIP map facts and stage history; profile and existing chat.

Catalog mutations update the existing shared Qolip catalog runtime. Product transfer keeps its secure request ID for an exact retry and publishes validated server results atomically. Storage retains source revision/request-ID rules and retry intents. Checkout bulk-return resolves every target before the first write, then preserves source sequential order and failed selection. Native Tasks socket admission is isolated from existing worker/warehouse sockets; background/focus/account retirement, ten-second first-message deadline, source reconnect delay and one repair budget are implemented and tested.

PDF export uses the original fonts/logo, source set/code grouping and ordering, UTC timestamp, A4 dimensions, filename and metadata, and actual page-number footers. Edit's int64 input is serialized as an exact JSON number token, avoiding Number rounding on dispatch. New dependencies were committed separately: Expo print/sharing/assets, Unicode 16 grapheme segmentation, pdf-lib and the native SVG scanner frame.

## Open items and inherited exclusions

1. No simulator or physical device was used. Native view hierarchy, keyboard/sheet animation, drag arbitration, camera handoff, Bluetooth/USB/Wi-Fi printing and PDF pagination need a development build on Android and iOS. The new native Tasks method and Expo print/share/assets dependencies require a rebuilt development binary.
2. Expo Camera does not expose V2's torch-availability signal; ready scanners may show a torch control on hardware without a torch. Full process-wide reliable scanner lease/decode-recovery equivalence is not established by the JS tests. Source eight-second startup/four-second release limits and original-account lifecycle guards are implemented; no hardware parity claim is made.
3. Centralized test/demo mode is intentionally deferred by project D3. GoDEX is intentionally excluded by D13. No replacement demo branch or GoDEX renderer was added.
4. JSON DTO sizes remain JavaScript numeric values; outbound Edit int64 text is exact, but displaying values above Number.MAX_SAFE_INTEGER from arbitrary server snapshots retains the existing shared numeric-model limitation. Ordinary 32-bit spec/set inputs retain source validation.
5. Existing opt-in guarded GET transport joins an independently started refresh rather than initiating credential refresh. Legacy checkout reads retain their original refresh path; new guarded read branches retain the project auth contract. Strict V2 equivalence for an otherwise idle401 credential refresh is not claimed; changing global authentication is outside this role port.

A read-only harness using 800×1000 makes those two tests pass (four of five pass). This is a source demo-state inconsistency, not a V4 live-transfer failure. V2 was never edited.
