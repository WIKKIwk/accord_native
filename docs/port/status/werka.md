## Deviations candidates

- `WerkaStore._pendingBreakdownItems` groups records with an empty supplier reference by trimmed supplier name, but `_pendingDetailItems` filters only by reference. Selecting one blank-reference group can therefore show all blank-reference records. Kept as V2 behavior; do not change without direction.
- With integrator direction, the new Werka store rejects late reads, bootstrap values and mutation-result projections from a replaced session or changed read scope; it also consults the actual active session by default on each snapshot read. It cannot itself force a rendered view to reread when auth changes, so integration still needs a tested notification/remount. New Werka mutations recheck the same identity, scope and permission immediately before every send. The unwired receive flow additionally keeps an instance-local uncertain-write lock after a failed send, including after refresh; this intentional safety difference is not cross-remount reconciliation. V2's singleton and write calls do not add these checks. This is an intentional safety difference; it does not cancel a server mutation or authorize an automatic retry after an uncertain result. A caller must retain the generation from before the write and treat an old or uncertain result as such. The QR-preview GET also checks the originating scope before each initial or refreshed send and after decoding, an intentional safety difference from V2. This is not a redirect-hop guard, request cancellation or a complete auth lifecycle solution.
