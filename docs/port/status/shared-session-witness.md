# Shared session witness candidate

Status: opt-in shared building block based on native main `56b34e72a91a8e1308df00d63dff40a899d21a69`. No role consumes it yet and no routes are enabled by this change. Role integrations must apply and test the consumer contract below.

`captureSessionWitness(session)` returns a frozen, issued snapshot only for the exact current Session while no tracked account transition is in progress. `isSessionWitnessCurrent(snapshot)` checks issuance, exact object, epoch, monotonic generation and current read-scope fingerprint. `subscribeSessionWitness(listener)` and `sessionWitnessVersion()` let an opted-in shell clear stale state when a transition or tracked access scope changes. A witness that has returned false is permanently retired, even if its old scope later returns. A consumer must capture once at shell or operation creation, subscribe and recheck immediately after subscribing, check the same witness at each async result and `authorizedFetch` before-send/401 retry, and invalidate on unmount/reset. Never silently recapture an old operation after a transition.

Tracked transition boundaries include login, logout/clear, different-object or conflicting queued `saveSession` calls, and the runtime account-switch operation from before reauthentication through installation or rollback. Failed logins and same-epoch A→B→A saves permanently invalidate prior witnesses. A same-object profile save with unchanged access scope, as well as an ordinary same-account token-only refresh, preserves the witness; a refresh changing access scope blocks captures through persistence and invalidates before retry. The runtime switch conservatively invalidates even when the selected account turns out to be the current account. Subscriber exceptions, including rejected promises, are isolated from authentication.

Limitations: this is an in-process observation, not a server authorization, transaction lock, native dispatch or redirect protection, or evidence that an already-sent mutation did not execute. An external in-place scope A→B→A mutation that never passes through an instrumented boundary is not observable; callers must not mutate session identity or scope behind auth and still need their own role/capability checks. The scope fingerprint mirrors `sessionReadScope` and must remain synchronized. If a tracked async transition never settles, capture remains blocked until it does. No fake success or automatic repeat of uncertain writes is provided here. React consumers must avoid recapturing from a stale screen merely because a transition has ended; the same-account no-op transition also requires a fresh validated shell. A callback is expected only to invalidate/redraw and must not initiate reentrant account mutations.

Validation for this checkpoint uses mocks, not real credentials or a backend. A no-subscriber native baseline (`56b34e7`) versus candidate comparison matched a normalized 70-event login/storage/profile/refresh/failed-login/rollback/clear trace, and a separate account-switch comparison matched same-account, normal switch, failed rollback and overlapping-operation traces. These are focused traces, not a proof for all scheduler interleavings or native phone behavior. The existing API results, storage order and exceptions are not intentionally changed; Worker and Preparation code is untouched.

`sessionWitnessTransitioning()` is a read-only boolean for a newly mounting shell to distinguish a tracked in-progress transition from an ordinary logged-out state. A fresh shell may subscribe, recheck, wait for the transition to finish, and then load the final active session; a previously issued stale witness must never be recaptured.
