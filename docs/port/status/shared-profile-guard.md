# Shared Profile optional session guard

Status: candidate for independent integration review. Existing callers that omit the optional guard or unavailable-settings message retain their previous default Profile behavior. This checkpoint is not a complete Admin role or a server-side authorization mechanism.

- `ProfileScreen` accepts an optional synchronous `isCurrent` predicate. Opted-in callers require it to return exactly `true`; false, thrown, asynchronous and reentrant results fail closed. Existing edit, picker, refresh, save and asynchronous state callbacks recheck it. The camera permission result is rechecked before launching the camera. An already-invalid witness does not render the Profile view or avatar.
- Profile GET, nickname PUT and avatar POST pass the optional check to the existing `authorizedFetch` before initial send and 401 retry, and recheck after response/body work and before applying profile data or avatar bytes to session/cache. Guarded responses with a different role/ref are rejected before mutation; legacy callers retain the old parser behavior. A legitimate scope-changing Profile response invalidates the captured witness when `saveSession` observes the changed scope, so that old view cannot treat the old witness as current again.
- Guarded avatar downloads use the existing cache and omit credentials as before, but do not publish a late download after invalidation. Guarded initial downloads do not share an unguarded in-flight request. Existing no-guard cache paths, request signatures and Worker/Preparation defaults remain unchanged. The opt-in settings-unavailable message removes the Settings/PIN entry and its iOS switch-PIN read; omitting it retains the previous view. Admin's localized notice and route integration are separate.
- Fifty-eight focused old/new Profile tests pass, including an actual shared-witness failed-login rollback with the old session token still active, 401 retry blocking, token-only retry, mismatched response identity, post-body/cache invalidation, stale UI callbacks, photo preparation, and unchanged Worker/Preparation view defaults. The iOS typecheck and lint passed. Full working-tree Node, Android typecheck and bundle results belong to the role integration checkpoint; no live backend, credentials, simulator or device was used.
- The guard cannot retract a request already dispatched or prove a timed-out/401-retried mutation did not commit. `authorizedFetch` does not recheck on every GET redirect hop, and the JS-to-native dispatch interval is not atomic with a session transition. Native image components may independently fetch an avatar URL; their platform dispatch/redirect behavior remains unverified. A deliberately hostile rejected Promise with a throwing `constructor` getter can prevent rejection observation, although it still fails the guard and sends nothing; no global handler or foreign-Promise mutation was added. Scope/identity trimming and malformed server-response behavior can differ from Dart. Real Profile settings/security callbacks remain hidden for the opted-in Admin until separately guarded and reviewed.
