# Chat secure transport: partial, not integrated

- Branch starts from main `2b6bacf49e1dd09afb9cddf8c335d340a8f36e01`. This is a new-role opt-in security transport, not a claim of full Chat parity. Worker and preparation routes retain their existing transport. No role opts in yet.
- The Android prototype constructs the fixed Chat endpoint from the authenticated HTTPS origin and a short-lived ticket, uses a separate OkHttp client with `CookieJar.NO_COOKIES`, no authenticators, and both redirect flags disabled. It does not override TLS trust or hostname verification and does not enable cleartext. The repo declares OkHttp 4.9.2; the actual Gradle resolution is not yet verified.
- The iOS prototype constructs a WSS endpoint from the HTTPS origin, disables cookies, credential storage and cache on a new ephemeral session, refuses redirects, and uses normal system server-trust handling. Non-server-trust authentication challenges are cancelled. The trusted origin is supplied by the authenticated JS session; arbitrary compromised app JavaScript is outside this boundary. Expo module bindings require a new development build and are not yet device-verified.
- Host Android tests compiled the actual core with Kotlin and Maven Central OkHttp 4.9.2/Okio 2.8.0. A synthetic self-signed `localhost` TLS certificate and PKCS#12 fixture are generated only in the test scratch directory. The test builds a test-only client SSL context trusting that certificate, with the real secure-client settings retained; it does not alter the system trust store. Production code contains no custom trust manager, hostname-verification bypass or cleartext exception. The test verifies no synthetic cookie/authorization header, no redirect to a second loopback server, open/send and cancellation.
- Host Swift core typechecked with the macOS Command Line Tools Foundation SDK. Its real production session configuration and redirect delegate were tested using synthetic loopback `ws://` requests constructed exclusively in the host test. Production request construction rejects non-HTTPS origins and creates WSS. This is macOS host evidence, not an iOS build or iOS runtime test.
- A new role must explicitly pass `livePolicy="secure"` to its **role-nested** `ChatRouteProvider` and use `useSecureChatUnreadState(session)` in its persistent shell. The provider supplies the policy before list/thread hooks render, so they do not fall back to React Native's legacy socket while the shared runtime is starting. The existing standalone `/ios-chat` and `/android-chat` routes remain legacy: new secure roles must not navigate to them. No existing route has been switched. Future role integration must verify all entry points and nested route pushes.
- `useSecureChatUnreadState` reports `loading`, `ready`, `degraded`, or `unavailable`, with `count: null` until an actual server list has been applied. In Expo Go or an older development build without this module, it reports `unavailable` with a development-build-required message. Secure list/thread routes expose the same real error instead of falling back. This error is an intentional native-build limitation, not a V2 text parity claim.
- Native socket IDs are process-scoped monotonic strings and fail closed on exhaustion. JS checks the exact active session, its original server/role/ref, closed state and socket ID; logout/account-switch reset hooks stop the subscription and abort a pending ticket. A late event already queued before native cancellation cannot reach a newer socket. Host contracts cover delayed old events, fresh-ticket reconnect on a failed native send, background/resume, and per-module shutdown isolation. Android module shutdown cancels its private OkHttp client and closes its dispatcher/pool; Swift invalidates its own URLSession.
- The socket ticket is still requested by the existing `authorizedFetch` path. Installed `whatwg-fetch` maps `credentials: 'omit'` to XHR `withCredentials=false`, but its implementation does not implement the requested `redirect: 'manual'`; native Android networking derives its normal redirect-following OkHttp client, and iOS `RCTHTTPRequestHandler.mm:147–159` repopulates destination cookies during redirects. The new module's guarantee covers its WebSocket handshake, not the whole ticket-and-socket flow; resolve this before integrating secure roles.
- A separate secure native POST could send the fixed empty-body ticket request using the same private no-cookie/no-redirect clients, return status/body and support cancellation and a 10-second deadline. Preserve f119's 2xx/JSON handling and the existing one-time 401 retry with session/generation checks. However `refreshSession` reauthenticates via `authenticateAccount`, whose ordinary RN fetch sends phone/code credentials and has the same redirect exposure. A safe retry needs a separately reviewed, role-scoped secure reauthentication seam; silently omitting refresh would be a behavior deviation. No shared auth code or credentials were changed.
- Checks at this checkpoint: 1,180/1,186 Node tests pass; the six failures are the existing preparation Android Expo UI `createModifier` resolution failures. iOS TypeScript and uncached Expo lint pass. Android TypeScript reports the same nine pre-existing worker errors. Focused Chat, secure-policy, account-switch and preparation-Chat contracts pass; the host-only native tests described above pass.
- Expo autolinking search discovers the local module for Android and Apple. No simulator, device, live backend, production ticket, production cookie, or OS security settings were used or changed.
- The selected Mac has no Xcode or iPhone SDK. An Android compile is pending the official Gradle 9.4.1 download; the generated, ignored wrapper is pinned to the checksum returned by `https://services.gradle.org/distributions/gradle-9.4.1-bin.zip.sha256`. Do not merge until the native builds, route integration, account switching, Expo Go failure handling and device-level behavior have been independently checked.
