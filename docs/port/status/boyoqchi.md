## Checkpoint verification

- Draft regression review: V2 `ReturnedPaintDraftStore` awaits `SharedPreferences.setString` and awaits queued writes before clear (`returned_paint_draft_store.dart:191-214`). Expo FileSystem 58.0.13 declares `File.move` as `Promise<void>` and documents that it mutates the file URI (`src/internal/NativeFileSystem.types.ts`); its native iOS and Android implementations also update that URI. The adapter awaits the move and cleans a reference to the original temporary URI. Nine draft tests pass, including controlled delayed/URI-mutating moves, restart/read, failed-move cleanup, repeated writes and clear-after-write. These filesystem tests are mocks; native-device verification is still needed.
- Draft recovery review: both SDK platforms delete an existing target before overwrite. The mock now models that exact delete-then-fail window and checks restart reads, successful URI-mutating moves, delayed backup-copy ordering and failure, successive writes, read races, scope isolation and backup-first clear. Eleven file-adapter and five draft-state tests pass. Backup restores the last completed primary when the primary is absent; the limits above remain open.
- Draft serialization review: controlled asynchronous SDK-style tests reproduce the former clear/edit temp collision, and now check same-scope write/clear/edit ordering, failure followed by queued and later writes, independent scopes, and multiple adapters sharing the same module queue. Sixteen file-adapter and five draft-state tests pass. The queue protects mutations sharing this JS module instance; it does not resolve the broader clear/edit or load/clear race described above.
- Draft account isolation review: role-local tests use placeholder HTTPS hosts with identical actor/request IDs to check separated drafts and images, account/role/request changes, hashed filenames, delayed old-session reads and moves, stale save/clear callbacks, and reauthentication of the same account. Legacy actor/request files and backups remain untouched. The versioned isolation is an intentional security departure from V2; real-phone and safe legacy recovery remain open.
- Draft session review: the exact `activeSessionEpoch` accessor from main `27f615f` is used with `sessionReadScope` and active-session identity.
