# Opt-in guard for Qolipchi read-only integration

Status: **reviewed candidate only, not routed or merged**. This checkpoint is based on native main `21aa4a10963580c6c7ed1cb80f8536bbe6f1f711`, after the separate unrouted Home content checkpoint. It changes only the shared transport and adds a read-only observer beside the existing refresh function. It does not change `authenticateAccount`, ordinary login/logout, notifications, or the separately unanswered login 307/308 redirect policy.

`authorizedFetch` accepts a sixth, explicitly opt-in `{ readWitness }` argument for GET/HEAD only. It requires synchronous literal `true`, latches rejection, observes rejected thenables, and fails closed on throwing, asynchronous, reentrant or revoked checks. The caller must supply a non-revivable original session witness; a scope or identity comparison alone is insufficient. The guarded path pins the validated method even if an input getter changes, prepares the request arguments, then checks immediately before each initial, redirect and 401-retry fetch. It checks after the first response and after joining a refresh. A timed-out request's gate closes so a later redirect cannot dispatch. An already-dispatched native fetch cannot be recalled or made atomic with a later session change.

On 401, the opt-in path can use an already-rotated token or observe an independently running legacy refresh of the same session and auth epoch, with its own witness checked before and after the wait. It neither starts nor cancels that refresh. If no successful independent refresh is available it raises `GuardedReadRefreshUnavailable`, code `guarded_read_refresh_unavailable`; it never launches credential authentication, initializes the saved-account store, upserts account secrets/metadata, writes the live session, or clears auth. This is a deliberate 401 parity limitation. Re-login and a fresh owner can recover, but no such control or route is supplied by this checkpoint. Independently initiated legacy refresh remains free to finish its own network and storage work after a guarded observer expires; that work is not attributed to or canceled by the guarded reader.

This conservative design replaces an earlier uncommitted guarded-refresh experiment. Independent review reproduced scope-changing and mid-storage revocation cases where that experiment could update saved credentials without updating the live session, as well as reentrant duplicate refresh. It was abandoned, not merged. Pre/post checks around multi-await account publication were insufficient; a native write already started was followed by additional metadata/chunk writes after revocation. No guarded refresh publication path remains in the candidate.

Legacy callers with no opt-in keep the original fetch expression and its evaluation order, redirects, cross-origin credential stripping, timeout, single-flight refresh, mutation invalidation, and image behavior. The additional observer does not participate in the legacy refresh. Independent review of the settled candidate found no remaining blocking issue in the guarded transport and passed 103 focused tests. Real iOS/Android fetch behavior and non-atomic dispatch still require a device check; the unanswered login redirect policy remains outside this change.
