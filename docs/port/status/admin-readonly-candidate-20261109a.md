# Admin read-only Work Map candidate

Base: main `bffbcc0044956653bb929be9139c3e121c650c8f`. Source: the read-only Work Map pieces of `port/admin` at `22397762f6fa69a2c0159eca58d9a9f8ac06ff21`, compared with clean V2 `f11910bb2c8c7081ce26770e69811b03fd0739ed`. This started as an unexposed integration candidate. Current integration evidence is appended below; the Admin role remains incomplete and its root release hold stays active.

- The existing Work Map page, apparatus catalog, opened-order detail, pending-order detail and saved-summary read paths explicitly supply the original per-operation `{ readWitness }` to the reviewed shared `authorizedFetch`. The prepared Closed history reader also supplies it, but no Closed history UI, sheet or route is connected. Page witnesses bind the original account/scope/route plus window generation, request and search; catalog witnesses bind the original account/scope/route and catalog generation; detail and summary retain the opening ticket and mounted/expanded lifetime. No image reader or mutation was connected.
- Original Work Map window, Move and workspace disposal/invalidation now retire before synchronous listeners can initiate reads. The loading publication is followed by a fresh generation check; a non-reentrant synchronous witness validator rejects malformed/async callbacks. The catalog transport uses each attempt's actual deadline so a timed-out attempt's opt-in gate cannot outlive its outer deadline. Failing-first fake-only tests reproduced the previous hazards.
- A follow-up fake-only audit found that reusing a mutable caller-owned window request could leave an old generation witness live, and an equivalent copied row/ticket could be accepted as detail authority. Window requests are now copied when received. Detail tickets are frozen, issued by that controller only for its exact current row, and checked by identity as well as generation and membership. Tests reproduce both previous failures and exercise the valid path; the actual two platform views pass the current row object. This is a conservative Admin-only authority boundary, not proof of native layout or source UI parity.
- The opt-in is additive to main's `src/apparatusApi.ts` before-send seam. Existing calls without the new witness retain their old `authorizedFetch` arguments and defaults; the older `3191135`/`636bbba` apparatus changes were not applied. Post-body/decoder checks remain separate from dispatch checks. Shared auth, notifications, Worker and Preparation source, and blocking login redirects are unchanged.
- Current main has physical Admin route files, but each platform root layout returns only a redirect to `/`, and there is no Admin home target. The role remains unreachable through that held root. Work Map components and shell context are not newly exposed by this integration. The shell context refers to Home/Activity readers which have **not** been promoted to this transport; do not expose the shell or Admin routes without a separate closure review. An exposure regression enforces this hold.
- An unaided 401 fails with `guarded_read_refresh_unavailable` instead of starting a refresh; joining an independently running refresh may retry under the original witness. This is an intentional safety/availability difference from V2; a reviewed user-facing recovery decision is still required before exposure. The fake-only tests cover each reader at a stale 302 and 401, stale during a joined refresh, post-body retirement, and a valid independently refreshed catalog read.
- The existing shared native sheet registers plain `navigation.goBack()` on close/unmount. An older Work Map detail or Closed sheet can therefore pop an independently stacked newer route on invalidation. The targeted POP proof at Admin commit `2239776` is not integrated into the shared route or this candidate and does not establish native transition completion. A reviewed route-specific close boundary and real-device dismissal checks remain mandatory before connecting detail or Closed history. The Held Closed history owner/sheet and all transfer, edit, live, image, printer and other actions remain unexposed.
- Source parity is incomplete: Work Map windows, summary metrics/cache, Closed expansion and log sheet, image/catalog presentation, actions, pagination, live updates, exact text, layout, accessibility and RTL still need their documented work and native checks. No backend, simulator/device, printer, SQLite-integrity retry, push or main merge was used.
