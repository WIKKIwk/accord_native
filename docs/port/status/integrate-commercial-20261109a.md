# Commercial role integration checkpoint

Base: main eae7e24d54c0352a7a0a58550ba59817d42ebd54. This branch merges the original Admin (2239776), Customer (a4ff5dd) and Supplier (15f4f07) tips. These roles are incomplete and have not had a device test.

- Admin and Customer root layouts redirect to the stable root unavailable screen. Their home targets are intentionally absent, including for overlapping worker/preparation capabilities. The original implementation remains in the role directories and source branch history. Admin is held because its alternate apparatus guard is not part of main and the existing main guard does not satisfy all Admin guard regressions. Customer is held because its store can update a shared runtime after requests complete without an independent session witness; delivery actions also lack an atomic account witness.
- Supplier has no home target; its notification-detail and create screens are not wired to routes. Its root shell can still be deep-linked by an authorized Supplier to overview, category, status, recent and profile pages; the existing shared profile screen also permits profile editing and logout. The unmounted notification-detail controller calls the shared supplier decision store after a response even if stopped; do not wire it before the account-switch decision is resolved. The original supplier branch retains the complete implementation.
- Main's `src/auth.ts`, `src/apparatusApi.ts`, `src/shared/notificationApi.ts`, and `src/shared/dispatchRuntimeStores.ts` were retained unchanged. This excludes Admin's alternate apparatus guard and auth changes, Customer's microsecond timestamp ordering and Dart whitespace/boundary cases, and Supplier's Dart-whitespace status parsing and `Exception:` error-string changes. Tests for the explicitly deferred notification behavior remain as TODOs with their assertions intact. Main's protected authentication and notification behavior is not altered.
- Admin's `pendingOrderApi.ts`, `productionOrderDetailApi.ts` and `productionOrderPageApi.ts` have optional guarded call paths; callers without a guard retain their previous path. Added shared notification-detail components are currently unmounted. All other Admin/Customer/Supplier role content and tests are preserved from their branches, subject to the conflicts described above.
- Conflicts: Admin `src/apparatusApi.ts`, `src/auth.ts`, `src/shared/appRoutes.ts`, `tests/authLoginRollback.test.cjs`; Customer `src/shared/appRoutes.ts`; Supplier `src/shared/notificationApi.ts`, `tests/dispatchRecordParser.test.cjs`. The main version won for protected shared flows and parser regression. The route addition was subsequently held to protect existing roles. The parser regression on main included all supplier assertions plus an additional legacy-status test.
- A candidate-only, untracked `node_modules` symlink points to the existing main dependency directory for local checks. It is not committed.
