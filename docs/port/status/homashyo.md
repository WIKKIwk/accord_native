## Scanner hold and evidence
- V2 `mobile_scanner` checks Android barcode corner points against the whole centered scan window and uses iOS Vision region of interest; it supports tap-to-focus and ML Kit auto-zoom. The candidate currently reads the entire preview and omits those actions, so it must not be connected or exposed.
- Expo SDK 58's [Camera documentation](https://docs.expo.dev/versions/v58.0.0/sdk/camera/) says bounds can be empty or incomplete. Installed Android transforms barcode corners into view coordinates; the iOS metadata and alternate detection paths require real-device coordinate verification. Expo exposes a numeric zoom prop and autofocus mode, but no scan-window/region, touch-focus point, or equivalent ML Kit auto-zoom API established by this audit. The installed CameraView suppresses identical detections for 500 ms, another behaviour to compare. No new native bridge is assumed. React layout-effect timing is only mock-tested; it does not prove native events or camera release timing on a device.
- The isolated V2 scan-window geometry tests passing 28/28 demonstrate V2 math only, not parity of camera crop, coordinates, focus or zoom on Expo. A real iOS and Android camera test and a safe verified solution remain prerequisites.
