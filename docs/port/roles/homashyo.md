## Role and navigation

- `AppSession.homeRoute` selects `AppRoutes.rawMaterialSplit` for `homashyo_rezkachi` with `raw_material.split`; `rawMaterialSplit` and `rawMaterialSplitHistory` deny another role even with the capability. Without the capability the role cannot open either. (`core/session/state/app_session.dart`, router capability/guard files; `raw_material_split_test.dart:655`.)
- `RawMaterialSplitDock` has Rezka and Profil, and the shared `RoleDock` appends Chat with the unread badge. Rezka, Profil and Chat replace the root. Drawer has Rezka, Rezka tarixi and Profil, selected by current destination. The existing Chat WebSocket is under a security hold; do not expose a role Chat route until the redirect/cookie issue is cleared. Source: `raw_material_split_navigation.dart:7–70`, `core/widgets/navigation/role_dock.dart:61–153`.
- Home header: `Rezka`; history action `Rezka tarixi`; device picker action `Printer tanlash`, both disabled while busy. History header: `Rezka tarixi`, back action `Orqaga` pops if possible, otherwise replaces with home; device picker disabled while busy. Both show a top loading indicator while busy and use the role drawer/dock.

## RawMaterialSplitScreen

Source: `raw_material_split_screen.dart:16–680`. State: initial/busy, account scope, pending stock command, pending issue command, snapshot/warehouses, optional source and draft rows, optional saved result, selected printer/transport, Wi-Fi printer (`godex` by default), errors and saved issue. `_locked = busy || pending != null || pendingIssue != null`. The pending operations persist by server and profile ref; they lock normal input and cannot be replaced by a new payload.

- Initial load sequentially reads pending stock, pending issue, then snapshot; after each asynchronous step checks the captured account scope. Error is shown verbatim. Warehouse text is `Omborlar yuklanmoqda`, `Ombor biriktirilmagan`, or `Ombor: <joined names>`.
- Pending stock text `Oldingi saqlash natijasini tekshiring.` with `Tekshirish va chop etish` retries the *identical* persisted command. Pending issue text `Oldingi muammo qaydi natijasini tekshiring.` with `Muammo qaydini tekshirish` retries that identical separate command. Both retry actions disabled while busy.
- Barcode input `Rulon QR / shtrix-kodi`, submit/arrow `Rulonni topish`, and `Skanerlash` are disabled while locked. Scan opens `showRawMaterialScanDialog`, which returns a detected or manually entered barcode or null on dismissal. Empty input does nothing. `rawMaterialBarcodeFromQr` keeps opaque strings and extracts barcode/epc/qr query or the last path segment of an absolute URL. Loading clears prior source and saved result; successful source lookup resets outputs to one empty row, waste and issue fields; response must include a revision. Scope checked after async calls.
- Selected device line is `Printer: <transport>`; for Wi-Fi the selector offers `GoDEX` and `Zebra`, default `godex`. GoDEX printing remains excluded by D13 and must be explicitly tracked rather than silently faked. Device picker is a dismissible bottom sheet opened by header or before stock save. It offers Wi-Fi discovered/manual servers, Bluetooth and local USB where supported; cancellation must not submit stock.
- Source shows item name, `<kg> kg · <width> mm · <micron> mkm` and optional `<length> m`, followed by `Ombor: <name>`. Each `<n>-rulon` has remove action `Rulonni olib tashlash` (disabled while locked or only one row), fields `Eni (mm)`, `Og‘irlik (kg)`, `Babina (kg)`, `Metraj (m)`, and `Netto: <net> kg` or `Netto: —`. All fields disabled when locked; changing any measurement invalidates saved issue and clears issue error. Net is gross minus bobina, strictly positive. Widths use six decimal places, minimum 355 mm, at most 100 rows, and total cannot exceed source. Width Done removes only wholly empty surplus rows when usable remainder is below 355 mm; never drops a partially filled row. `+ rulon` appears only on last row when current rows complete and at least 355 mm remains. Summary states are `Ko‘pi bilan <n> ta rulon · eng kam eni 355 mm`, `En to‘liq taqsimlandi`, `Qolgan <n> mm — atxot`, and `Qolgan <n> mm — yana rulon kiriting`; width errors are below the waste field as `<n>-rulon: <error>`.
- `Atxot (kg) *` is measured, never inferred. Balance is `Chiqish: <n> kg · Chiqindi: <n> kg` plus `Hisob teng ✓`, `Asl kg dan oshib ketdi`, or `Kiritilmagan: <n> kg`; invalid input yields `Og‘irlik, babina va 0 dan katta atxot kg ni kiriting.` If width plan complete, show `Yana rulon kerak: <n> mm` or `Atxotga ketadi: <n> mm`. `Saqlash va chop etish` validates all rows, width and waste first. Gross/bobina/length errors and exact fixed-six payload are in `rawSplitDraft.ts`.
- Waste discrepancy opens the inline issue section and scrolls it into view, not a replacement modal. Show the `RawSplitWasteCheck.message`, `Farq sababi` input (2–3 lines, max 1000, disabled while locked or already saved), current error, and `Muammoni saqlash` or saved message `Muammo saqlandi. Chop etish uchun atxot kg ni son bilan kiriting.` / `Muammo saqlandi. Endi chop etishingiz mumkin.` Issue note must be nonempty. If issue succeeds without source after retry, show snackbar `Muammo saqlandi`. An issue with invalid waste can be recorded but stock cannot save until numeric waste is entered; changing a measurement invalidates the saved-issue state.
- Save obtains a device if absent; cancellation means no stock mutation. Check captured scope, persist and submit the exact stock command, validate full returned result and remove pending key, then clear source/barcode and print each returned roll once. Stock is already committed before printing; on print error show `Omborga saqlandi. Chop etish: <error>` and never resubmit stock to retry printing. Success snackbar `Chop etildi`. Busy state resets and reload runs in finally. Local result must report `ok` and `status == done`, else `Printer natijani tasdiqlamadi`; Wi-Fi invokes `rawSplitPrint` for each child using `split_id`, barcode, selected driver URL/printer and `label` mode.

## RawMaterialSplitHistoryScreen

Source: `raw_material_split_history_screen.dart:17–277`. Initial/pull refresh reloads snapshot; duplicate reload while busy ignored. Loading, error (`Tarix yuklanmadi` with actual error and retry), and empty (`Hali bo‘lish tarixi yo‘q.`) are distinct. History cards preserve snapshot order and show `<source kg> → <output kg> kg`, warehouse, actual output count, waste, and local time. Issues follow under `Muammolar`; each shows source item, `check.message` and local timestamp. A selected printer line appears only when a printer exists, with Wi-Fi type when relevant. No synthetic counts.

Each result card opens a scrollable, dismissible `RawSplitDetailsSheet`; each issue opens `RawSplitIssueDetailsSheet`. Reprint single or all disables concurrent printing, prompts for a device if missing and leaves stock unchanged; failure `Ombordagi hisob o‘zgarmadi. Chop etish: <error>`, success snackbar `Chop etildi`. History back pops or replaces home. No explicit haptics are present.

## RawSplitDetailsSheet

Source: `raw_material_split_result_view.dart:230–460`. Header mirrors result card; detail rows are `Manba QR`, `Ombor`, optional `Vaqti`, and for linked issue `Farq` plus `Sabab`. For each output show net/width/micron/optional length, label name with output dimensions, optional `Brutto` and `Babina`, optional `Metri`, selectable barcode and `Shu rulonni qayta chop etish`. If no printer, show `Printer tanlash`, which closes the sheet before opening device picker; otherwise show printer and optional Wi-Fi selector. `Barchasini qayta chop etish` prints all. Block repeated actions while printing. Sheet is safely dismissible by system back, outside tap and swipe as Flutter bottom sheet defaults allow.

## RawSplitIssueDetailsSheet

Source: `raw_material_split_result_view.dart:463–574`. Show item name and check message, `QR`, `Asl` with source kg and entered atxot (or `kiritilmagan`), each `<n>-rulon` width/gross/bobina/net, `Sabab: <note>`, actor and local timestamp. End with `Muammo bo‘yicha rulonlar saqlangan.` when a history result references the issue, else `Muammo sababi qayd etilgan.` Dismiss like result sheet.

All static and dynamic source strings above and the full ledger text report require comparison on both platforms. The existing app's Chat hold and the GoDEX exclusion are explicit parity gaps.
