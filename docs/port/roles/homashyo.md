## RawMaterialSplitScreen

Source: `raw_material_split_screen.dart:16–680`. State: initial/busy, account scope, pending stock command, pending issue command, snapshot/warehouses, optional source and draft rows, optional saved result, selected printer/transport, Wi-Fi printer (`godex` by default), errors and saved issue. `_locked = busy || pending != null || pendingIssue != null`. The pending operations persist by server and profile ref; they lock normal input and cannot be replaced by a new payload.

- Initial load sequentially reads pending stock, pending issue, then snapshot; after each asynchronous step checks the captured account scope. Error is shown verbatim with the error color. Warehouse text is `Omborlar yuklanmoqda`, `Ombor biriktirilmagan`, or `Ombor: <joined names>`.
- Pending stock text `Oldingi saqlash natijasini tekshiring.` with `Tekshirish va chop etish` retries the *identical* persisted command. Pending issue text `Oldingi muammo qaydi natijasini tekshiring.` with `Muammo qaydini tekshirish` retries that identical separate command. Both retry actions disabled while busy.
- Barcode input `Rulon QR / shtrix-kodi`, submit/arrow `Rulonni topish`, and `Skanerlash` are disabled while locked. The scanner action keeps its QR-scanner icon. Scan opens `showRawMaterialScanDialog`, which returns a detected or manually entered barcode or null on dismissal. Empty input does nothing. `rawMaterialBarcodeFromQr` keeps opaque strings and extracts barcode/epc/qr query or the last path segment of an absolute URL. Loading clears prior source and saved result; successful source lookup resets outputs to one empty row, waste and issue fields; response must include a revision. Scope checked after async calls.
- Selected device line has a 20-point print icon and `Printer: <transport>`; for Wi-Fi the selector offers `GoDEX` and `Zebra`, default `godex`. GoDEX printing remains excluded by D13 and must be explicitly tracked rather than silently faked. Device picker is a dismissible bottom sheet opened by header or before stock save. It offers Wi-Fi discovered/manual servers, Bluetooth and local USB where supported; cancellation must not submit stock.
- Source shows item name, `<kg> kg · <width> mm · <micron> mkm` and optional `<length> m`, followed by `Ombor: <name>`. Each `<n>-rulon` has remove action `Rulonni olib tashlash` (disabled while locked or only one row), fields `Eni (mm)`, `Og‘irlik (kg)`, `Babina (kg)`, `Metraj (m)`, and `Netto: <net> kg` or `Netto: —`. All fields disabled when locked; changing any measurement invalidates saved issue and clears issue error. Net is gross minus bobina, strictly positive. Widths use six decimal places, minimum 355 mm, at most 100 rows, and total cannot exceed source. Width Done removes only wholly empty surplus rows when usable remainder is below 355 mm; never drops a partially filled row. `+ rulon` appears only on last row when current rows complete and at least 355 mm remains. Summary states are `Ko‘pi bilan <n> ta rulon · eng kam eni 355 mm`, `En to‘liq taqsimlandi`, `Qolgan <n> mm — atxot`, and `Qolgan <n> mm — yana rulon kiriting`; width errors are below the waste field as `<n>-rulon: <error>` in the error color. An invalid width also uses an error outline while the numeric field is enabled or focused; the source does not assign this outline to the other numeric fields (`_number:462–484`, width call at 619–620).
- `Atxot (kg) *` is measured, never inferred. Balance is `Chiqish: <n> kg · Chiqindi: <n> kg` plus `Hisob teng ✓`, `Asl kg dan oshib ketdi`, or `Kiritilmagan: <n> kg`; invalid input yields `Og‘irlik, babina va 0 dan katta atxot kg ni kiriting.` If width plan complete, show `Yana rulon kerak: <n> mm` or `Atxotga ketadi: <n> mm`. `Saqlash va chop etish` keeps its print icon and validates all rows, width and waste first. Gross/bobina/length errors and exact fixed-six payload are in `rawSplitDraft.ts`.
- Waste discrepancy opens the inline issue section and scrolls it into view, not a replacement modal. Show the error-colored `RawSplitWasteCheck.message`, `Farq sababi` input (2–3 lines, max 1000, disabled while locked or already saved), error-colored current error, and `Muammoni saqlash` or saved message `Muammo saqlandi. Chop etish uchun atxot kg ni son bilan kiriting.` / `Muammo saqlandi. Endi chop etishingiz mumkin.` Issue note must be nonempty. If issue succeeds without source after retry, show snackbar `Muammo saqlandi`. An issue with invalid waste can be recorded but stock cannot save until numeric waste is entered; changing a measurement invalidates the saved-issue state.
- Save obtains a device if absent; cancellation means no stock mutation. Check captured scope, persist and submit the exact stock command, validate full returned result and remove pending key, then clear source/barcode and print each returned roll once. Stock is already committed before printing; on print error show `Omborga saqlandi. Chop etish: <error>` and never resubmit stock to retry printing. Success snackbar `Chop etildi`. Busy state resets and reload runs in finally. Local result must report `ok` and `status == done`, else `Printer natijani tasdiqlamadi`; Wi-Fi invokes `rawSplitPrint` for each child using `split_id`, barcode, selected driver URL/printer and `label` mode.

## RawMaterialSplitHistoryScreen

Source: `raw_material_split_history_screen.dart:17–277`. Initial/pull refresh reloads snapshot; duplicate reload while busy ignored. Loading (no snapshot and busy), error (any non-null error, including an empty string), and empty (`Hali bo‘lish tarixi yo‘q.`) are distinct. The error surface keeps `Tarix yuklanmadi`, trims a nonempty error subtitle, omits a blank subtitle, and disables retry while busy. Error, empty and selected-printer messages keep their source icons and ordinary `Text` localization boundary; they are not `UrduAwareText`. History cards preserve snapshot order and show `<source kg> → <output kg> kg`, warehouse, actual output count, waste, and local time. Issues follow under `Muammolar`; each shows source item, `check.message` and local timestamp. A selected printer line appears only when a printer exists, with Wi-Fi type when relevant. No synthetic counts.

Each result card opens a scrollable, dismissible `RawSplitDetailsSheet`; each issue opens `RawSplitIssueDetailsSheet`. Reprint single or all disables concurrent printing, prompts for a device if missing and leaves stock unchanged; failure `Ombordagi hisob o‘zgarmadi. Chop etish: <error>`, success snackbar `Chop etildi`. History back pops or replaces home. No explicit haptics are present.

## RawSplitDetailsSheet

Source: `raw_material_split_result_view.dart:230–460`. Header mirrors result card with its cut icon; detail rows are `Manba QR`, `Ombor`, optional `Vaqti`, and for linked issue `Farq` plus `Sabab`. Each metadata row has a separate label and value, without a colon added to the label. These are ordinary `Text` in V2: raw warehouse, timestamp and reason values are neither trimmed nor localized, and a non-null empty timestamp still has its row. For each output show net/width/micron/optional length, label name with output dimensions, optional `Brutto` and `Babina`, optional `Metri`, selectable barcode and `Shu rulonni qayta chop etish`. If no printer, show `Printer tanlash`, which closes the sheet before opening device picker; otherwise show printer and optional Wi-Fi selector. `Barchasini qayta chop etish` prints all. The per-roll, select-printer and reprint-all actions have printer icons; block repeated actions while printing. Sheet is safely dismissible by system back, outside tap and swipe as Flutter bottom sheet defaults allow.

## Open integration and verification

Both branch routes now connect the native home, history, detail sheets, scanner confirmation, shared device picker and source-derived controllers. Home/History retain their content while busy feedback appears under the header: SwiftUI uses its native indeterminate spinner and Compose uses its native indeterminate linear indicator. Home restores source error emphasis, invalid-width feedback, note visible line limits and scanner/print icons using existing native fields and controls. Its iOS inputs show one visible label and name the native field for accessibility. Native focus, VoiceOver, line wrapping, Dynamic Type and RTL behavior remain unverified. Home and History start their initial reload in a layout effect before the intended first painted frame; actual phone/native timing is still unverified. Manual scanner entry starts lookup directly as in V2. Camera detections still require explicit confirmation because the scanner lacks V2 scan-window filtering, tap-to-focus and auto-zoom. The discrepancy form requests native scrolling on Android and iOS 17+; iOS 16 does not support Expo’s target modifier, and iOS currently scrolls instantly instead of V2’s 200 ms animation. Native scroll timing, localization, navigation timing and device behavior remain open. `rawSplitPrintRuntime.ts` contains bridge, Wi-Fi Zebra and support-preflight code for a future reviewed release, not currently available actions. The production safety hold blocks all printer selection and printing, as well as stock and issue writes and their retries, until durable acknowledgment and same-scope reconciliation are established. GoDEX, offline USB and iOS Bluetooth also retain their independent documented restrictions. The shared Profile uses a session witness guard, while Settings/PIN is unavailable pending its own guard. Chat is wired through the shared safe transport; shared Chat UI and device checks remain open. Existing drawer, controls, printer bridge and native sheets are reused; protected roles are unchanged. All static and dynamic source strings above and the full ledger text report require comparison on both platforms.

## Session integration boundary

The role shell captures a main `SessionWitness` and epoch when it mounts, subscribes and rechecks, and disposes its controllers and picker on invalidation. A stale ticket is never recaptured. API, storage and print operations require that original ticket. Pending command keys remain account-scoped across login sessions. The witness is not a server or native-dispatch lock and cannot undo an already sent operation; unsupported in-place scope changes and native/device timing remain open. Demo-token actions fail closed. See the status file for the remaining test-mode, response identity and PIN limitations.
