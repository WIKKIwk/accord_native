## AdminHomeScreen

V2: `lib/src/features/admin/presentation/admin_home_screen.dart:20`. `AdminShell` is in `widgets/admin_shell.dart`; `AdminStore` is in `features/admin/state/admin_store.dart`. The same home component is reused under the role/capability routing for Admin, sales manager and brigader. Use the existing native shared drawer, dock, cards and FAB/menu facilities where they can preserve the behavior below; do not duplicate a ready component.

- Title: sales manager uses the literal V2 `userRoleLabel` `Sotuv manageri`, brigader uses `Brigader`, all other profiles use localized getter `adminRoleName`. The selected drawer destination is the session's home route. The dock's active tab is home.
- The screen listens to `RefreshHub`; when a new version has topic `admin`, reload. After its first frame, it starts `AdminStore.bootstrapSummary()` only when the profile has `party.supplier.read`. Pull-to-refresh invokes the same gated reload, including for short content. On leaving an opened child route and returning, reload. Prevent duplicate route openings until the prior navigation and reload finish.
- If summary permission is absent, do not request the summary and display the capability-filtered action list. For sales managers hide the create-item, create-user, users and production-map-test candidates even if their routes are otherwise open; sales action cards omit their leading icon. Others show each candidate's icon. Candidate order, exact localized keys and route targets are represented in `src/admin/adminHomeModel.ts` directly from `_adminHomeActions`.
- With summary permission, before the initial load show the loading indicator while `loadingSummary && !loadedSummary`; show the retry state if `summaryError != null && !loadedSummary`. Retry invokes reload. Otherwise show, in this order, only routes `AppRouter.canOpenRoute` permits: factory map (`adminFactoryMapNavTitle`), quick orders (`adminQuickOrdersTitle`), open order (`adminOpenOrderTitle`), work map (`adminWorkMapNavTitle`). Cards display the title and an empty value, with no user-count cards. A later refresh error does not hide already loaded content.
- Each visible card opens its named route and refreshes after return. If a destination is not yet implemented, record it as an Open item rather than inventing a destination. Route capability checks must use the verified shared V2 guard rather than a new approximation. The `adminHomeModel` currently depends on the existing V4 `canOpenRoute`; its f119 drift still needs integrator review.
- The source has no direct haptic call in this screen. Exact back behavior, drawer destination details, dock primary FAB overlay dismissal and every destination's screen contract remain in the separate shell/overlay audit. Do not mark these as verified based on the home model.
