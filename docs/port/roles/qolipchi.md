# Qolipchi UI contract

Baseline: `f11910bb2c8c7081ce26770e69811b03fd0739ed`. This contract is incomplete: the block screen below is specified; the remaining surfaces have only been inventoried. An inventory entry is not permission to mark a surface as ported or assume its states and actions.

## Blocks: `QolipBlocksScreen`

Source: `features/qolip/presentation/qolip_blocks_screen.dart`; matcher: `features/qolip/qolip_search_matcher.dart`; translations: `core/localization/app_localizations__productionTranslations_resplit_collection_11.dart`. Entry is the `qolipBlocks` drawer destination. The `qolip.manage` capability guards the route. Logic: `useQolipBlocks`, `QolipBlocksState`, `qolipBlocksData`, `qolipUpdateBlock`, `qolipDeleteBlock`, `qolipErrorMessage`.

- The native top bar is a search field. Its leading menu button opens the role drawer. The trailing profile action is hidden while search has focus. The field initially is empty; typed text is trimmed for matching without altering the displayed input. Clear returns it to empty. Hint is `qolip.blocks.search` (`Blok qidirish`). Match using the existing Qolip normalized, keyboard-aware, fuzzy query against block name and warehouse. Keep server order; do not sort.
- On entry call `qolipBlocksData`. While the first request is pending and no data exists, show a loading indicator. Failed read shows `qolip.blocks.load_failed` (`Bloklar yuklanmadi`) with retry. A completed empty or no-match result shows `qolip.blocks.empty` (`Blok topilmadi`), even when the search is empty. Empty and nonempty list states offer pull-to-refresh. During a refresh, retain existing rows until the new request resolves; a failed refresh replaces them with the retry state. The most recent requested read supplies the visible result.
- Each row shows its block name and warehouse. Tapping has no action. Long press opens a dismissible action sheet containing `qolip.action.edit` (`Tahrirlash`) and `qolip.action.delete` (`O‘chirish`). No further sheet opens while a block action is saving.
- Edit opens an alert with title `qolip.blocks.edit_title` (`Blokni tahrirlash`), autofocus text field `qolip.blocks.name` (`Blok nomi`) prefilled with the current name and capitalized for typing, plus `qolip.action.cancel` (`Bekor qilish`) and `qolip.action.save` (`Saqlash`). Submit from the keyboard is equivalent to Save. Cancel, an empty trimmed name, or a trimmed name equal to the current trimmed name has no effect. Otherwise send the trimmed name with the original block. On success show `qolip.blocks.updated` (`Blok tahrirlandi`) then reload. On failure show the localized `qolipErrorMessage` with fallback `qolip.blocks.update_failed` (`Blok tahrirlanmadi`).
- Delete opens an alert titled `qolip.blocks.delete_title` (`Blokni o‘chirasizmi?`) and interpolates `qolip.blocks.delete_message` (`{name} bloki butunlay o‘chiriladi.`) with the block name. Cancel does nothing. Confirm `qolip.action.delete` sends the original block once. On success show `qolip.blocks.deleted` (`Blok o‘chirildi`) then reload. Failure shows localized `qolipErrorMessage` with fallback `qolip.blocks.delete_failed` (`Blok o‘chirilmadi`). A successful write followed by a failed reload shows both the success and failure notices, as V2 does.
- No special permission-denied or offline view exists: the read failure uses the retry state, and write failures use the localized notice. V2 does not define a custom back guard or haptic for this screen; dismiss the current dialog/sheet first, then use native back navigation. Drawer destinations replace the current route; selecting the current one only closes the drawer. The role's home destination returns to an existing home route or removes the preceding stack and opens home. The bottom dock has no active tab here and routes to home, molds, tasks and chat; there is no primary FAB on this screen. Profile and chat must reuse the existing native surfaces. Where a destination has not yet been ported, it remains an explicit open item rather than a dummy action.

## Home: partial logic notes, not a complete surface contract

Sources: `qolip_home_screen_widgets_part_01.dart`, `qolip_home_screen_models_resplit_part_01.dart`, `qolip_home_screen__QolipHomeScreenState_methods_01.dart`, `qolip_home_screen_refresh.dart`. Entry is `qolipHome`. `qolipHomeLogic.ts` and the partial `QolipHomeState` port initial/manual block loading, ordering, location caching, debounced search and quiet refresh state. `useQolipHome` now connects focus, app resume, account reset, shared Qolip location revisions, app preferences and an after-frame scheduler when mounted. It has no screen caller yet; actions must emit the shared revision only at the corresponding V2 call sites. Actions, grid and navigation still need implementation and further contract review.

- Load blocks and warehouses, removing names that trim empty. Apply the locally saved `qolip.home.block_order` keys by trimmed lowercased block name, then append unseen server blocks in their original keyed order. Duplicate normalized names collapse to the last block value while preserving the first key position. Dragging to a valid different position reorders and preserves the currently selected block; persist the resulting keys.
- A nonempty search waits 160 ms before loading location lists for every ordered block. A block's failed location read contributes an empty list. Reuse Qolip search against item name/code, mold code, size, block, warehouse and cell label. Count matching locations by their own normalized block name and uppercased cell label, including repeated matches. Ignore a result once the search generation is stale. Clearing search cancels the pending work and clears counts.
- Home retains a current-account snapshot. Returning or resuming may request a quiet refresh after a 30-second cooldown; a forced locations revision can queue another refresh. Read blocks and every block's locations, keep old locations for failed reads, reject stale account/generation results and preserve selected block by normalized key. Compare exact ordered warehouse/block fields and every location identity, code, name, quantity and position field before updating. A failed refresh leaves the visible snapshot intact and clears the cooldown so a later return can retry.

Grid source: `qolip_home_screen__QolipBlockGrid_resplit_class__QolipBlockGrid_resplit2_methods_01.dart`, `_static_methods_01.dart`, and `qolip_home_screen_declarations_part_03.dart`. The table has letter columns A–Z, numbered rows 1–13 and a pinned numbered column. Group locations by their trimmed uppercase cell label; an empty label is unplaced. Show the number of distinct nonempty labels, the sum of all location quantities and, if nonempty, the number of unplaced entries. V2 includes unknown nonempty labels in occupancy and total even if the fixed grid cannot display such a label. Empty cell tap starts attach; occupied cell tap opens its detail; long press requests that cell's QR print. The occupied-cell sheet lists its items in server order, allows unplaced items or items from other nonempty cells to move in, and supports individual take/move or long-press selection and batch move. A selected ID selects every visible entry with that ID; selection mode is on whenever the ID set is nonempty. Buttons to add or move an unplaced/other-cell item are disabled in selection mode. `qolipGridLogic.ts` ports these grouping, selection and stat rules only.

The full home FAB, grid interactions and layout, create/attach/take/move sheets, QR scanner, print, drawer, dock, back behavior and exact text still need source review. Do not route this partial model as a home screen.

## Cell placement: `_QolipAttachSheet` in cell-placement mode

Sources: `qolip_home_screen_models_resplit_part_02.dart`, `qolip_home_screen__QolipAttachSheetState_methods_06.dart` and `_methods_07.dart`, `qolip_home_screen_helpers_part_05.dart`, `qolip_search_matcher.dart`, and the generic M3 picker. An empty grid cell opens this sheet with its block, row and column; a caller may also provide an initial product. Choose the initial block by exact name and warehouse, or the first block if no match. Show `home.cell_attach` (Qolipni joyga qo‘shish), `home.location` (Joy), block plus cell, and a product field `home.code_or_product` (Qolip code / mahsulot) with `home.mold_code_or_product_hint` (Qolip code yoki mahsulot nomi). A selected product shows its name, falling back to code, and its trimmed mold code and size; show a `home.mold_label` (Qolip) field when every selected product has a spec. The save action is enabled only with block, row, column and one or more selected products all having specs. A saving request disables further saves. The title also offers `home.qr_scan_tooltip`; the real camera scanner and lookup must be connected, not imitated.

Start the placed-code lookup as the sheet initializes. Read locations for each distinct, trimmed, nonempty block name in parallel; a code is placed only if its row is nonempty and its column is not null, including zero. Trim and lowercase nonempty codes. The picker lazily loads up to 20,000 products with `withQolipOnly`, then keeps only saved specs with a nonempty trimmed code, positive size and not in use. Deduplicate eligible codes case-insensitively in original order and exclude codes already placed in any block. Keep the future for each lookup for the sheet lifetime, including failures. Picker title is `home.mold_select_title` (Qolip tanlang), search hint `home.mold_code_customer_search` (Qolip code, mahsulot yoki customer nomi), with pages of 80. Match product name, code, item group, mold code, positive size and customer names using the existing Qolip fuzzy/keyboard search. Raw pages retain source order; the picker sorts the accumulated visible rows by `searchRelevanceScore` for a nonempty query, stably preserving source order on ties. A row shows product name or code, then trimmed mold code, size and item code. Its identity is trimmed lowercase mold code. A picker holds at most eight cached query futures before clearing the cache on a ninth distinct query; closing it cancels pending search work. The M3 picker waits 220 ms after a query edit before a fresh first page, discards stale responses and requests the next page near the scroll end. Loading shows a spinner; failure shows the existing server-disconnected text and retry; an empty result uses the existing no-records text. A long press enters multi-selection, after which taps toggle choices keyed by trimmed lowercase mold code. Selection survives searches and page changes, and the confirm control returns products in selection order; its tooltip is `action.confirm_selected`.

Choosing one product closes the picker and fills the sheet. Multiple selection closes the picker, then asks `home.place_confirm_title` (Qoliplarni joylaysizmi?) and `home.place_confirm_message` ({count} ta tanlangan qolipni {block} • {cell} yachaykaga joylaysizmi?), with `action.cancel` (Bekor qilish) and `action.place` (Joylash). Cancel makes no request. Confirm immediately saves the selected products; it does not wait for the sheet Save button. Save one product at a time in selection order with quantity one, retaining only products with specs. Continue after each failure, with no rollback. All succeed: close the sheet with its block and show `home.saved_one` or `home.saved_many` with code/count and cell; the home caller refreshes that block. Partial success: leave it open and show `home.place_partial` ({success} ta qolip joylandi, {failed} tasi joylanmadi). All fail: leave it open and display the first error through `qolipErrorMessage` with `home.place_all_failed` fallback (Qoliplar joylashtirilmadi). Account-reset guards must prevent remaining writes from crossing sessions; disclose partial work rather than presenting it as a transaction. Back or drag dismisses the picker or sheet normally; no custom haptic is specified.

`qolipCellPlacement.ts`, `QolipCellPickerState`, `QolipCellPlacementState` and their hooks implement these read/search/save rules and reuse the existing APIs. The sheet, multi-select picker, scanner, cell grid and caller refresh are not wired, and no platform or device parity is claimed.

## Set name dialog: `QolipSetNameDialog`

Source: `features/qolip/presentation/qolip_set_name_dialog.dart`; exercised by the name-flow widget cases in `test/qolip_set_names_test.dart`. Entry: the rename action on a managed set. Logic: `QolipSetNameState`, `useQolipSetName`, existing `qolipRenameSet` and `qolipErrorMessage`.

Open with the set's current name in an autofocus text field. Title is `qolipManagementText('rename')` (`Komplekt nomini o‘zgartirish`) and label is `qolipManagementText('name')` (`Komplekt nomi`). V2 limits input to 160 user-perceived characters (grapheme clusters), uses sentence capitalization and a Done keyboard. Cancel closes without a request. Save and Done send the raw current field text to `qolipRenameSet`, which separately normalizes whitespace and validates 1–160 Unicode code points and prohibited controls. A successful server result closes the dialog and returns the saved set. An error keeps the original text and shows the localized `qolipErrorMessage` with `qolipManagementText('rename_failed')` fallback (`Komplekt nomi saqlanmadi`); any edit clears the error. A duplicate name must not be treated as success. While saving, disable input, cancel, save, backdrop dismissal and hardware/native back; show a progress indicator. No separate haptic or refresh is specified in this dialog; the caller reloads after a successful result.

Both native dialog views exist but are not wired to a sets screen. iOS uses its native grapheme-aware 160-character field limit. Android's installed Compose field truncates by UTF-16 code units, so the native limit is intentionally not applied until a faithful grapheme limit is available; the API validation still runs. This is an open parity item, not a completed dialog.

## Reworks: `QolipReworksScreen`; mileage sheet: `_QolipMileageSheet`

Sources: `qolip_reworks_screen.dart`, `qolip_mileage_sheet.dart`, `qolip_reworks_screen_test.dart`. Entry: `qolipReworks` in the drawer. Controller: `QolipReworksState`; APIs: `qolipReworks(status: all)`, `qolipReturnFromRework`, `qolipMileage`. A real secure V2 request-ID generator is still required before wiring the return action.

Read all entries on entry. While each load or refresh is pending, V2 shows the loading indicator; error uses retry and pull-to-refresh reloads. Keep only selected IDs that remain open after a successful read. Search trims and lowercases the input and performs literal substring matching on mold code, set ID, item code and item name; unlike other Qolip screens this is not fuzzy or keyboard-mapped. The top search hint is `qolipReworkText('search')` (`Mahsulot, komplekt yoki qolip kodi`). The title is `qolipReworkText('title')` (`Peredelkadagi qoliplar`), with tabs `open` (`Peredelkada`) and `history` (`Qaytganlar`). Switching tabs clears selection and is disabled while saving. Empty states use `empty` (`Peredelkada qolip yo‘q`) and `history_empty` (`Qaytgan qoliplar yo‘q`).

Group visible rows in original order by nonempty set ID, otherwise mold code. A group title joins distinct nonempty item names, falling back per item to item code; if none exist use the group key. Show set ID below. Open groups and rows have checkboxes; the group checkbox selects or deselects its visible rows and rows also toggle on tap. Returned rows have no checkbox and tap opens mileage. A trailing mileage button opens the sheet on either tab. Preserve list scroll and unaffected rows when a return succeeds.

When open rows are selected, show `return_selected` (`Tanlanganlar qaytdi ({count})`) above the dock. Before and after confirmation compare the current session read scope with the scope used for the list. A changed scope shows `session_changed` (`Sessiya o‘zgardi. Sahifani yangilang.`) and sends nothing. Confirmation title/action use `return` (`Qaytdi`), body `return_confirm` (`{count} ta qolip qaytdi deb belgilansinmi? Ularning probegi 0 dan boshlanadi.`), with `qolip.action.cancel`. Sort selected IDs and preserve one secure request ID for repeated attempts of the same ID signature after a lost response; a changed selection gets a new ID. Saving blocks selection, tab changes and another return. On success replace matching rows from the server in place, invalidate older pending reads, clear selection and retained ID, notify the shared Qolip location revision and show `returned` (`{count} ta qolip qaytdi`). Do not reload the list just for this success. Failure leaves rows and ID for retry and displays `qolipErrorMessage` with `failed` (`Peredelka amali bajarilmadi`) fallback.

Mileage sheet displays `mileage` (`Probeg tarixi`) and the selected mold code, loads `qolipMileage`, shows loading or retry, then `current` (`Joriy probeg: {meter} m`) only when tracking is enabled and current meter is present, otherwise `not_started` (`Probeg hisobi hali boshlanmagan`). Show cycles in reverse source order; each has `cycle` (`{meter} m`) and local start/end date, or `active_cycle` (`Joriy davr`) for no end. Date format is `dd.MM.yyyy HH:mm` in local time; invalid input is shown unchanged. Format meter to two fixed decimal places then strip trailing zeroes and the decimal point. Sheet drag/back behavior is normal; V2 lists no custom haptic.

The controller, both platform reworks views and mileage-sheet openers exist, but they are not routed and the real request-ID source remains unavailable. The injected ID factory is mandatory and has no production fallback. Android reuses the existing compact 65% native wrapper; its effective inset behavior needs phone verification. The iOS wrapper offers 50% or 90%, so exact 65% height remains open without changing protected Worker files.
