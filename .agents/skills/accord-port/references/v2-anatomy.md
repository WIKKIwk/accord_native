## Reading split code

`part 'x.dart'` and `part of` merge files into one library, so a private `_helper` used in one file
can be defined in any other part. Find it with a search across the library's folder, not by opening
neighbouring files. `extension MobileApiAdminItemsAstPart01 on MobileApi` is only a splitter name:
the real owner is `MobileApi`, so tag `@v2 adminItemUoms`, not the extension.

## Roles

`userRoleFromJson` lowercases and trims. It maps `omborchi` to `werka`, and it **throws** on an unknown
role, so port it as a throw and not as a fallback.

| JSON value | Role in `roles.json` |
|---|---|
| `aparatchi` | `aparatchi` |
| `rezka_master` | `rezka`, also an apparatus operator (`isApparatusOperator`) |
| `boyoqchi` | `boyoqchi` |
| `homashyo_rezkachi` | `homashyo` |
| `material_taminotchi` | `material` |
| `customer` | `customer` |
| `supplier` | `supplier` |
| `brigader`, `sales_manager` | `brigader` |
| `tayyorlov_masteri` | `preparation` |
| `qolipchi` | `qolipchi` |
| `werka`, `omborchi` | `werka` |
| `admin` | `admin` |

Where a role lands is decided by `AppSession.homeRoute` in `core/session/state/app_session.dart`. What it may open
is decided by `AppRouter.canOpenRoute` and the capability map, listed above.

## Current V4, as of 2026-11-05

- It only runs the print-apparatus worker. `src/app/index.tsx` sends every session to the worker UI,
  with no role routing.
- `npx tsc --noEmit -p tsconfig.ios.json` passes. `tsconfig.android.json` reports 10 known errors. `node --test tests/*.test.cjs` passes 151 of 151.
- iOS navigation is in `src/app/ios-worker/` with native tabs. Android navigation is inside
  `src/WorkerScreen.tsx`.
- Chat exists only on iOS. `src/components/ChatThreadScreen.tsx` is a stub that Android currently ships.
- V4 uses `new Error(<Uzbek string>)` in most places and has no port of `MobileApiException`.
- It has no localization, no saved accounts, no push, no printing and no self-update.
- It targets Expo Go today, with no `modules/` folder, `eas.json` or `expo-dev-client`.
