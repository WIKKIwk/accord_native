# Admin native presentation

The Android observer watches **native window-tree detachment**, not the compositor's last animation frame. That observer does not present, close or identify a particular dialog implementation. The additive Android and iOS owned-sheet foundations are described below.

Precisely, completion means the original root's real `View.OnAttachStateChangeListener.onViewDetachedFromWindow` event was observed after arming. Android calls that listener before clearing `mAttachInfo`, so `isAttachedToWindow` may still be true during the event. The registry does not infer completion from that flag, a child/marker callback, descendant cleanup, or elapsed time. See [AOSP View.dispatchDetachedFromWindow](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/view/View.java).

Place a real `View` with `collapsable={false}` and a unique opaque `nativeID` inside the intended Expo dialog using `RNHostView`. A marker outside the dialog cannot establish that dialog's completion. A zero-size overlay must preserve existing content layout and spacing.

`readAdminPresentationWindowCapability('android')` returns unavailable for old/missing/incompatible native binaries. Available means the protocol exists; it never means a presenter is ready. There is no fallback completion. Rebuilding the development app is required to add this module; no build or device validation has been run for this checkpoint.

1. Capture the actual RN marker's native tag and a never-reused ticket (ASCII letters/digits followed by letters/digits/`:._-`, maximum160 characters).
2. Await `observer.arm(tag, ticket)`. Native acknowledgment occurs only after the original non-Activity root's attach listener is installed and the marker/root/activity/token checks still pass. An unattached resolved marker waits for its actual attach event; no polling runs. `cancelPending(ticket)` cancels this wait. If it returns false because arming already completed, await the arm result and cancel that exact receipt.
3. An accepted close can be queued while arming. Remove the React dialog only after acknowledgment, then await `observer.waitForDetach(receipt)` exactly once. Marker/ref removal is not completion. A genuine root detach observed before `waitForDetach` is retained.
4. Recheck original account, mounted lifetime, dialog ID/generation and accepted closing intent before completing domain work. This module cannot supply those JS guards.
5. Release original receipts with `cancel(receipt)` on owner retirement. Activity/module destruction cancels pending work; it never reports normal completion. Cancelling does not itself dismiss a window.

The native core keeps opaque used-ticket tombstones for the module lifetime to prevent stale pending cancellation from targeting reused tickets; it releases view/listener/reply references on completion/cancellation. No Compose dependency, reflection, window inventory, timer, marker-detach completion or inferred readiness is used. The module references the app's installed React Android SDK plus the existing Material1.13.0 and AndroidX Core1.18.0 artifacts with `implementation`: Android AAR dependencies need their native resources. No JavaScript package or Compose compiler plugin was added. Native binary/classpath compilation remains unverified. Public Android root/token checks establish a separate native window; actual marker placement inside the intended dialog remains the caller's responsibility.

Source anchors inspected: installed Expo `ConverterContext.findView`/`AppContext`, RN `FabricUIManager.resolveView`, `ReactFindViewUtil`/`BaseViewManager.nativeID`, and Expo UI `RNHostView` native reparenting. Local module autolinking defaults to `./modules`.

The shared `useAdminPresentationWindow` consumer captures one original identity/observer/ticket and its original authority callbacks. Allocate the ticket once with `createAdminPresentationWindowTicket` (the app's existing `expo-crypto` UUID). Supply live original `isCurrent` and accepted `isClosing` checks; a captured stale render's closing boolean is insufficient. Pass the actual in-window marker tag to `owner.markerTag`, let `state.present` control React removal, and complete domain work only from `onDetached`. The consumer retains content through arm acknowledgment, watches that exact root, rejects an unexpected root loss before accepted closing, and cancels exact pending/armed resources on retirement. Its StrictMode cleanup microtask only releases resources; it never acknowledges dismissal. This infrastructure does not supply a Root presenter, top-modal authority or native readiness before arming.

## Android owned sheet foundation (unconnected)

`sheetCapability()` exposes protocol1/`owned-android-presentation-and-dismissal` and the named `AdminSheetPortal` view. Its immutable original configuration matches iOS below and additionally requires actual Source `barrierOpacity`; no dim amount is guessed. One real React child is forwarded through Expo's public GroupView API into a separately owned Material BottomSheetDialog. The touch root retains the original ThemedReactContext, Fabric surface/registered tag, dispatchers and extra-window notifications; actual size updates use the public shadow-node API. No new JavaScript package or Compose plugin is needed.

Readiness joins genuine OnShow with actual owned Decor/root/content attachment and exact native identities. Activity association uses ACTUAL attached Decor WindowManager.LayoutParams.token and application type/display. Normal Dialog View.applicationWindowToken values are distinct; they are retained only as per-window identity, never equated across windows. Own-window edge-to-edge/adjustResize, actual parent system-bar icon appearance, explicit dim and configured corners do not change Activity window modes. Native HIDDEN/SETTLING are not removal receipts: normal dismissal requires actual OnDismiss plus the original Decor detach. Pending-show resource retirement always dismisses an already issued show, even before attachment; private cleanup is neither Source acceptance nor a public completion acknowledgment.

Compiled JVM/Foundation transaction and window-policy tests plus public SDK/AOSP source inspection do not compile or run Android views. Kotlin/Gradle/AAPT/Fabric/Material semantics, touch/layout/keyboard/rotation, exact Source styling and physical nested survival remain Open. Root admission also requires the separate original retirement cleanup protocol and source adapters; the module capability alone cannot enable it.

## iOS owned sheet foundation (unconnected)

`sheetCapability()` exposes protocol1/`owned-uikit-presentation-and-dismissal`; it is a module capability, not an account/route/readiness result. The `AdminSheetPortal` native view requires `layoutRoot=true`, one original React content root and `configuration` with never-reused `presentationTicket`, original `parentTicket`, real parent marker `parentViewTag`/`parentNativeID`, positive `heightPoints` and nonnegative `cornerRadius`. Its portal anchor must remain in that exact parent's native subtree; it never adopts a latest top controller or key window. The current configuration is immutable, so live Source rotation/keyboard/detent geometry still needs an adapter.

`onSheetEvent` distinguishes `shown`, blocked `attempt`, `willDismiss`, `cancelled`, actual `didDismiss`, `closeAccepted`, `closeJoined`, `failed`, `retired` and native `layout`. Only the owned UIKit presentation completion emits shown. `dismissalEnabled` controls native interactive dismissal; the actual native transaction disables content interaction while closing. `acceptedClose` carries the original `presentationTicket`, opaque `closeTicket` and either an exact native transaction or null for independent original Source acceptance. A null intent atomically binds only this same immutable presentation's current actual native transaction, including when bridge delivery crosses a native gesture or an early physical dismissal. `closeAccepted` echoes the bound native transaction; an explicit transaction must match exactly. Repeating the original close/null is idempotent and cannot be retargeted into a different intent. Neither a request, appearance nor React unmount proves dismissal or Source acceptance.

The Root chain still needs a pending-native-dismiss state, a narrow original cancellation lease, a distinct genuine retirement cleanup receipt and the exact Source result/route-removal join. No source sheet or Admin route is connected by this foundation. Foundation/JVM transaction host cases verify only the pure native transaction cores; UIKit/Kotlin/Expo/Fabric/ObjC++ semantic compilation, touch/layout/keyboard, native cleanup and physical nested-window behavior remain unverified. The existing Android observer cannot be substituted for an owned native sheet presenter.
